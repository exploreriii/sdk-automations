# 6.14 Defining a label

Three calls on 2026-09-16 under the App's installation token, against the personal
sandbox: read a label the repository lacks, create it, read it back, create it again.

## Question

Whether the App can define a mapped label the repository lacks, with a colour and a
description of its own, and tell beforehand that the repository lacks it — so a label a
maintainer created is never touched (D202).

## Method

`harness/src/run-6.14.ts`: `GET /repos/{o}/{r}/labels/{name}` on an unused name, `POST
/repos/{o}/{r}/labels` with `color` and `description`, the same `GET`, the same `POST`.
The lead deleted the label afterwards.
